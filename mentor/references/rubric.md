# Milestone review rubric

Pass requires ALL THREE, demonstrated in the current session:

1. **Works.** The deliverable functions as specified, verified against the real repo (run it, plan it, test it: evidence, not assertion).
2. **Understood.** Unaided explain-back: the learner walks through what they built and why it works, without notes or file-peeking, ideally reconstructing from the original problem rather than reciting the lesson; and answers at least one prediction question correctly.
3. **Failure-aware.** "What breaks first?" answered with a real failure mode and its consequence.

Grade each axis: strong | adequate | gap. Any `gap` = milestone fails.

**Fourth axis, checked later: Transferred.** Same underlying concept, meaningfully different surface problem, little or no framing, spaced (a later session). Not part of the milestone gate; scheduled through the ledger ("Next useful step" on the concept card, run during sparring or wrapup of a later session or in the plan retrospective). Passing it moves the concept to `transferable`.

Rules:
- Questions are calibrated to what this milestone taught and the learner demonstrated. No trivia (flags, API names), no concepts merely encountered, no escalation because early answers were good.
- Deferred exam ("next time") = fail today. Retriable next session, no penalty.
- Effort, confidence, and time pressure are not axes.
- A wrong answer is diagnosed before it is graded. If the missing piece was never taught, that is a plan gap: journal it, teach it, re-ask.
- A fail's gap list is concrete: what is missing + what demonstrating it looks like. It is the next session's agenda, not a punishment.
